## 总目标

一次性解决用户对两个核心展示区的反馈：

1. **首屏航空网络**：线路太少、端点悬空、机场重叠、美国轮廓不可信、日期变化看不出来、整体比例瘦长；
2. **飞机轮转故事**：关键信息只有7–11px、专业名称难懂、计划时刻间隔和实际地面周转混在一起、传播/恢复关系没有被讲清楚。

最终网站需要从“看起来像航空主题仪表板”变成“普通访客能够顺着真实数据理解延误如何在同一架飞机的连续航班中移动”。

### 1A. 月度航线网络

按 Task 02 规则从 `p0_flights.parquet` 生成40–50条真实美国本土月度主要机场对：

- `Cancelled != 1`；
- `Diverted != 1`；
- 双向合并为无向机场对；
- 保存 `origin / dest / flights / delayRate`；
- 每个端点都有同一坐标源中的经纬度；
- 生成规则和选择数量写入数据元信息。

### 1B. 轮转故事字段

按 Task 03 规则补齐：

- 计划起飞 UTC；
- 实际起飞 UTC；
- 计划到达 UTC；
- 实际到达 UTC；
- 起飞/到达延误；
- 相邻航段的计划时刻间隔；
- 实际地面周转；
- 延误分钟变化；
- 传播、追回但仍晚、完全恢复等关系状态。

### 1C. 重新选择语义不干净的故事

必须检查当前 `N210WN` 的 `0分钟计划时刻间隔 / 45分钟实际周转` 案例。

- 优先用 `ActualTurnMinutes` 选择真实紧周转案例；
- 如果找不到语义干净案例，用“延误被放大”等更可靠的第四种故事替换；
- 保持4个故事、真实机尾连续、机场连续和时间单调。

### 1D. 数据阶段门槛

数据阶段完成后先运行并确认：

- 每条月度航线端点都有坐标；
- 无重复无向机场对；
- 4个故事和20个左右真实航段完整；
- 所有相邻连接器指标可从源字段复算；
- Python 全量测试通过。

如果数据语义未通过，不得进入UI阶段。

## Phase 2：首屏网络重构

完整执行 Task 02，特别强调以下用户验收点。

### 2A. 两层网络

- 40–50条真实月度航线作为低亮度底网；
- 4个轮转故事作为红/琥珀/薄荷高亮层；
- 每条可见线路至少一个沿同一贝塞尔曲线运动的信号；
- 每条线路准确连接到画布节点；
- 绘制顺序：底网 → 故事高亮 → 节点 → 标签/HUD。

### 2B. 密集机场

- 所有机场保留真实坐标；
- 屏幕距离约18–24px的机场做视图层聚合；
- 每个聚合组最多一个常驻文字标签；
- 悬停/点按后在固定HUD列出组内机场；
- 航线仍连接底层真实机场坐标；
- 桌面最多10–12个常驻标签，手机最多5–6个；
- 不允许东北走廊、西海岸标签堆成字符团。

### 2C. 地图与比例

- 使用有明确来源的 contiguous U.S. 边界数据，删除手工折线；
- 边界和机场使用同一投影函数；
- 1366×768 下地图宽高比约1.55–1.75，优先接近16:10；
- 文案/地图约40–43% / 57–60%；
- 中文标题不使用 `Arial Narrow`，不再显得又高又窄；
- 1366×768 下完整看到地图和日期控制区。

### 2D. 日期反馈

- 用31天真实延误率 min–max/分位数归一化；
- 同步影响节点光晕、线路透明度、粒子速度/亮度和背景能量；
- 增加31日迷你趋势图和选中日高亮；
- 增加由分位数计算的全国低/中/高压力等级；
- 最低日与最高日截图必须肉眼可区分；
- 明确这是全国信号，不是逐机场每日状态。

## Phase 3：轮转故事重构

完整执行 Task 03，特别强调以下用户验收点。

### 3A. 普通话故事名称

主标签使用结果句，例如：

- 连续4班仍在晚点；
- 晚到后被下一班追回；
- 实际只在地面停了X分钟；
- 先传递，后来追回。

`延误级联 / 紧周转 / 传播` 可以保留为次级技术标签，不能继续作为唯一主标题。

### 3B. 航段卡与地面连接器

航段卡优先展示：

1. 航班号；
2. 起讫机场；
3. 计划/实际起飞与到达；
4. 起飞/到达延误。

相邻航段之间独立展示：

1. 衔接机场；
2. 计划时刻间隔；
3. 实际地面周转；
4. 上一班到达晚点 → 下一班起飞晚点；
5. 继续传播 / 追回但仍晚 / 完全恢复。

传播状态属于连接关系，不要只塞在下一张航段卡角落。

### 3C. 可读字号

桌面最低要求：

- 航班号15–17px；
- 机场代码28–34px；
- 计划/实际时间13–15px；
- 字段标签至少11–12px；
- 延误数字17–22px；
- 连接器和结论至少12–14px；
- 正文至少14px；
- 非关键元数据不得低于10px。

不要再用7–9px承载故事关键信息。

### 3D. 响应式故事线

- 桌面使用连续横向时间线或可逐步点选的故事轨道；
- 1366×768 至少清楚展示3个航段和2个连接器；
- 手机改为航段/连接器交替的纵向时间线；
- 不能依赖悬停才能获得关键内容。
