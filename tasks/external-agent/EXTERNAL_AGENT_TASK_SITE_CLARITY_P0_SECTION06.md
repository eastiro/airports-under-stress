## 3. 页面结构

### 3.1 一眼层：必须默认可见

保留问题式标题：

- 中文：`航班排得越密，延误越容易继续吗？`
- 英文同步表达。

标题下先放一条动态结论，不要先讲定义：

- 默认 60 分钟明确展示“排班较松 42.27% / 排班较密 66.15% / 相差约 24 个百分点”；
- 切换 30/90 后，这句话和三个数字必须随真实数据变化；
- 用“继续晚点”而不是单独使用“传播率”。

默认可见的关键数字最多三个：

1. `排班较松`：继续晚点比例；
2. `排班较密`：继续晚点比例；
3. `两组相差`：百分点。

不得在这三个主卡片里出现：

- 冻结事件；
- frozen events；
- Gate / CONDITIONAL GO / OMA；
- Spearman / 四分位一致率；
- 中间 50% 组；
- 样本数、中位数、P90。

固定保留一句白话边界：

> 这里只看到“排班更密”和“晚点继续”经常一起出现，不能证明排班密造成了延误。

可以在同一句或紧邻次级句提到天气、空管、跑道容量等因素，但不要形成长警告段。

### 3.2 理解层：必须默认可见

保留 30 / 60 / 90 分钟切换，默认 60。按钮附近直接写：

> 这三个按钮改变的是：围绕计划起飞时刻，统计多大时间范围内安排了多少起飞与到达；不是观察延误持续多久。

避免“观察窗口”作为唯一标签。中文优先叫“统计范围”，英文用自然对应表达。

保留低组与高组条形对比。条形图旁只使用“排班较松 / 排班较密”和“继续晚点”语义。中间组不在默认条形图中争夺注意力。

### 3.3 研究细节：默认收起、点击展开

使用原生可访问的 `<details>` / `<summary>` 或等价键盘可操作组件，标题：

- 中文：`查看研究细节`
- 英文：`View research details`

展开后组织为三个语义小组，可在一个 details 内分块，不要做多个层层嵌套折叠：

1. **这是怎么算的**
   - 低 / 中 / 高三组的真实样本数与传播率；
   - 样本单位改成“次航班衔接”或自然等价，不出现“冻结事件”；
   - 计划总架次中位数与 P90；
   - 说明“计划拥挤”来自时刻表，不是当天实时堵塞，也不是安全或能力排名。
2. **换一种统计范围，结果还稳不稳**
   - 30/90 相对 60 的 Spearman 与四分位一致率；
   - 60 显示主口径说明，不伪造自相关指标；
   - 明示 30 分钟四分位一致率约 51%，只作敏感性参考。
3. **为什么不做机场排名**
   - 55 个机场和全国样本范围；
   - OMA 高组 82、门槛 100、`CONDITIONAL GO`；
   - 不展示机场不代表更差，样本不足不等于 0%。

研究词可以保留在这个展开层，但每个块先用人话标题，不制作术语词典。
