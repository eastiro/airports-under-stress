# External Agent Task 02 — 重构首屏航空网络的连接、地图与日期反馈

> 执行入口：`EXTERNAL_AGENT_TASK_02_03_MASTER.md`。本文件是首屏网络详细规格，不要脱离 Master 单独启动。

## 背景

Task 01 已经完成 V0.5 首屏原型，但用户在实际查看第一屏后指出：

1. 一些航线没有准确连接到可见机场节点，部分线路端点像悬在空中；
2. 很多线路没有明显的移动信号点；
3. 机场很多、航线很少，画面不像网络；
4. 机场标签大量重叠，尤其是西海岸城市群和东北走廊；
5. 当前手绘边界不像美国本土；
6. 拖动或播放 5 月日期时，看不出网络压力发生了什么变化。

这不是简单调色任务。需要重构首屏网络的数据层和绘制层，同时保持数据诚实。

## Codex 已确认的事实

- 当前首屏主节点：42 个。
- 当前故事航段：20 段，其中只有 19 条不重复的起讫路线。
- 4 个故事涉及 14 个机场。
- `CRW / DLH / PDX / SBN / SMF` 五个故事机场不在当前 Top 42 节点集合中，因此存在“线路端点没有节点”的真实问题。
- 当前所有 42 个机场标签都以绝对定位按钮直接放在地理坐标上，没有碰撞处理。
- 当前美国轮廓是 `NetworkHero.tsx` 内的一组手写归一化折线点，不是可识别、可溯源的美国本土边界。
- `data/processed/p0_flights.parquet` 含 611,735 条航班记录和 `Origin / Dest / Cancelled / Diverted / DepDelay` 等字段，可以生成真实月度航线网络。
- 当前每日延误率最低为 13.5%，最高为 32.15%；现有强度变化对节点半径影响很小，用户肉眼无法稳定识别。

## 最终目标

首屏应同时存在两层真实网络：

1. **月度航线底网**：由 2026 年 5 月真实航班记录聚合出的主要机场对，形成足够丰富但不混乱的全美连接网络；
2. **代表性轮转高亮层**：继续使用 4 个真实机尾号故事的 20 个连续航段，用红/琥珀/薄荷突出传播和恢复。

用户第一眼应能看懂这是美国航空网络；每条可见线路应连接到节点；日期变化应能明显改变“整网紧张程度”，而不仅是数字变化。

## 任务 A：生成真实月度航线底网

从 `data/processed/p0_flights.parquet` 生成首屏专用聚合数据。

### 聚合规则

- 只使用 `Cancelled != 1` 且 `Diverted != 1` 的实际执行航班。
- 只保留美国本土范围内、拥有可复核经纬度的机场。
- 把双向航线合并为无向机场对，例如 `LAX–SFO` 与 `SFO–LAX` 合并。
- 每条机场对至少包含：`origin`、`dest`、`flights`、`delayRate`。
- 按 `flights` 降序选择 40–50 条主航线；建议默认 48 条。
- 不得用随机连接、最近邻、Delaunay 三角网或视觉补线冒充真实航线。
- 4 个轮转故事的路线继续独立保留，不要混入底网后丢失状态语义。

### 数据产物

优先在 `scripts/build_v0_data.py` 中增加可复现生成逻辑，并在 `web/app/v0-data.json` 中新增独立字段，例如：

```json
{
  "network": {
    "selection": "Top 48 undirected route pairs among operated contiguous-U.S. flights",
    "routes": [
      { "origin": "LAX", "dest": "SFO", "flights": 2056, "delayRate": 0.0 }
    ]
  }
}
```

具体数字必须由数据计算，不得照抄示例。

如果需要扩充机场坐标：

- 继续使用 OurAirports `airports.csv` 的原始经纬度；
- 将本项目需要的经纬度保存为可复核的静态子集；
- 在数据文件或 README 中保留数据 URL、字段字典、检索日期和 Public Domain 声明；
- 不依赖浏览器运行时网络请求。

## 任务 B：保证线路、节点和移动信号完全一致

- 月度底网的每个 `origin / dest` 必须存在对应坐标和画布节点。
- 4 个轮转故事涉及的所有机场必须强制加入节点集合，即使不属于压力榜 Top 42。
- 航线、移动粒子、节点必须调用同一个投影函数、同一个起点/终点对象和同一条贝塞尔曲线路径。
- 每条可见月度底网线路至少有一个低亮度移动粒子；代表性轮转线路使用更醒目的状态色粒子。
- 先绘制底网，再绘制故事高亮线路，最后绘制节点，避免线路盖住节点。
- 不允许线路在距节点几像素的位置停止，也不允许出现有线无节点的悬空端点。
- 重复方向或重复故事航段可以共享几何线路，但动画相位应错开，避免粒子完全重合。

## 任务 C：解决标签重叠

不要继续把所有机场代码作为永久可见的绝对定位按钮。

### 桌面端

- 所有机场都保留 Canvas 节点，但默认只显示最多 10–12 个主要机场标签。
- 标签优先级综合考虑航线量、压力指数和地理覆盖，不能只把东北部机场全标出来。
- 使用明确的碰撞规避或预先验证的偏移布局，默认状态下标签矩形不得相互覆盖。
- 鼠标悬停或键盘聚焦节点时，可在单独的 tooltip/HUD 中显示机场代码、城市、压力指数和月度航线量。

### 手机端

- 默认最多显示 5–6 个标签。
- 不得因为屏幕窄就让东北走廊、西海岸标签堆成一团。
- 允许减少粒子数量，但不能退化成静态图。

### 无障碍

- Canvas 外保留简洁、可访问的网络摘要和主要机场列表；不要用 40 多个互相覆盖的透明按钮假装可访问。
- 中英文 ARIA 文案同步。

### 全国视图的密集机场处理

全国尺度下不要试图同时展开每一个机场名称，也不要为了躲标签而移动真实机场坐标。

- 所有机场点和航线端点继续保留真实投影位置。
- 对屏幕距离小于约 `18–24px` 的机场做视图层聚合；阈值应随画布宽度/DPR 调整，而不是修改地理数据。
- 聚合组可以显示一个共享光晕、主要机场代码和 `+N` 数量，例如东北走廊或洛杉矶都会区；悬停/点按后在固定 tooltip/HUD 中列出组内机场。
- 航线仍连接到组内机场的真实底层坐标，不连接到伪造的聚合经纬度。
- 每个聚合组默认最多显示一个文字标签；标签优先级按月度航线量，其次压力指数。
- 当机场没有发生碰撞时才显示独立标签。
- 不要求引入 deck.gl；如果继续使用 Canvas，应实现一个确定性的屏幕空间碰撞/聚合算法，并为相同输入得到相同结果。
- 参考原则：专业地图会通过 collision priority 隐藏低优先级重叠标注，而不是让所有文字同时出现。

## 任务 D：替换美国本土轮廓

- 删除当前手工归一化折线。
- 使用可注明来源的美国本土边界 GeoJSON/TopoJSON，或从公开边界数据生成一个足够简化的静态轮廓文件。
- 推荐美国 Census Cartographic Boundary 或 Natural Earth；必须记录具体来源 URL、版本/检索日期和许可说明。
- 只显示 contiguous U.S.，不把阿拉斯加、夏威夷或海外领地硬塞进主画布。
- 边界与机场必须使用同一套经纬度投影函数。
- 最终截图中，即使隐藏机场标签，普通人也应能识别出美国本土形状。
- 不使用需要 API key 的地图服务，不做浏览器运行时地图请求。

## 任务 E：让日期变化肉眼可见

每日数据仍然只是全国层面信号，不得伪装成逐机场逐日数据。

### 强度映射

- 用 31 天实际延误率的 `min–max` 或分位数归一化，而不是仅除以月平均值。
- 日期变化至少同时明显影响：
  1. 节点外圈光晕大小/亮度；
  2. 底网线路透明度；
  3. 粒子速度、亮度或可见数量；
  4. 画布背景能量或扫描层强度。
- 低压日与高压日并排截图时应能直接分辨，但不能使用闪烁、抖动或大面积刺眼红色。
- 日期切换做 300–600ms 平滑过渡，避免突然跳变。

### 控件反馈

- 在滑杆附近增加真实 31 日迷你柱图或折线脉冲图；选中日期必须有清晰高亮。
- 增加“低 / 中 / 高”或等价的全国压力等级，阈值由 31 天分位数计算并在代码注释中说明。
- HUD 数字、压力等级、迷你图选中项和网络强度必须同步。
- 继续保留说明：这是全国每日压力信号，不是逐机场实时状态。

## 任务 E2：修正首屏过窄、过高和字体过度压缩

用户明确反馈当前首屏“瘦长”。Codex 核对后确认：

- 当前网络面板实测约为 `749×588`，宽高比约 `1.27:1`，更像竖向仪表板而不是横向航空态势图；
- 首屏网格约为 `36% 文案 / 64% 地图`，但文案栏仍只有约 420px；
- 标题字体变量以 `Arial Narrow` 开头，并使用极紧的负字距和 `0.82` 行高，导致中文大字特别高、窄、挤。

### 桌面布局要求

- 以 `1366×768` 作为主要验收视口。
- 地图主体宽高比应在 `1.55:1–1.75:1` 之间，优先接近 `16:10`；不要继续使用近似正方形的 590px 强制最小高度。
- 首屏在 1366×768 下应看到完整地图主体和日期控件，不应只露出控制区的一小部分。
- 文案/地图建议约为 `40–43% / 57–60%`，具体可微调，但文案栏不能被压成细长竖条。
- 减少首屏无意义的上下空白，让标题、说明、地图和控制区形成一个横向整体。

### 标题要求

- 中文首屏标题不得继续优先使用 `Arial Narrow`。
- 使用正常宽度、适合中文的系统无衬线字体，例如现有 body 字体栈中的 `Microsoft YaHei UI / PingFang SC / Segoe UI`；不要为此引入远程字体请求。
- 字号建议控制在 `clamp(56px, 6.2vw, 96px)` 附近，行高约 `0.9–0.96`，负字距显著弱于当前 `-0.075em`。
- 标题仍可保留实心/描边两行对比，但不应占满整个文案栏并压迫正文。
- 英文也要检查宽度和换行，不能为了中文修正后让 `Pressure is / breathing` 溢出。

### 手机布局要求

- 手机继续上下排列，但标题不得使用 `18vw` 造成过高的视觉压迫。
- 首屏进入地图前的文案长度和空白应收紧；在 390×844 下至少应看到地图的明确开头，而不是几乎整屏只有标题。

### 禁止的“修复”

- 不通过整体缩小网页、CSS `transform: scale()` 或降低浏览器缩放解决比例问题。
- 不牺牲地图宽度来给每个机场标签腾位置。
- 不把标题拆成三到四行来掩盖窄栏问题。

## 任务 F：测试和浏览器验收

### 自动检查

至少增加以下验证：

- 月度底网路线数在 40–50 之间；
- 不存在重复无向机场对；
- 每条底网和故事线路的两个端点都有坐标；
- 4 个故事的 20 个航段全部保留；
- 坐标来源和美国边界来源存在于项目文档/数据元信息中；
- `npm.cmd test` 通过；
- Python 数据测试通过；
- App 源码 lint 通过。

### 浏览器检查

必须实际检查：

1. 桌面首屏默认画面；
2. 390×844 手机画面；
3. 低压日（当前数据的最低日）与高压日（当前数据的最高日）；
4. 播放、暂停、拖动日期；
5. 中英文切换；
6. reduced-motion；
7. 浏览器控制台无持续 warning/error。
8. 1366×768 下首屏地图宽高比、标题宽度和日期控件完整性。
9. 东北走廊、洛杉矶都会区等密集区域的聚合/标签展开状态。

重点确认：

- 没有悬空线路；
- 每条可见线路都有移动信号；
- 默认标签没有明显重叠；
- 美国轮廓清晰可识别；
- 低压日和高压日的网络视觉差异肉眼可见；
- 后半页功能和布局没有变化。
- 默认全国视图中，每个密集机场组最多一个文字标签，机场名称没有堆叠成不可读字符团。
- 1366×768 首屏不再呈现细长地图或细长标题栏；地图与文案的横向比例自然。
