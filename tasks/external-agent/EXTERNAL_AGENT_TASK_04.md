## 用户反馈原意

本轮必须解决以下普通访客真实遇到的问题：

1. 首屏只看得出延误率高时节点变大、变亮，不知道取消率和传播率有没有映射到地图；
2. 聚合节点虽然显示“2机场 / 3机场”，但只能悬停，鼠标移向机场列表时面板消失，无法真正选择机场；
3. 页面没有解释地图、压力榜和全国指标分别覆盖多少机场、什么样本；
4. MSY 的 `82.7` 容易被误读为“第83名”，压力指数、排名和满分没有说清；
5. 压力榜按取消率或航班量排序时，行内仍固定显示起飞延误和传播率；应该按什么排序就突出展示什么数据；
6. 中文模式仍大量展示英文机场、城市、州和航司名称；
7. 精神航空只有354条月度记录，与完整月份航司混排不合理。用户明确要求：**直接从航司对比移除精神航空，不做异常事件卡，也不要在页面额外讨论它。**

## 已核实的当前数据范围

不得混淆以下数字：

- 原始 BTS 2026 年 5 月数据：611,735 条记录、347 个始发机场、13 家报告航司；
- 同时满足“月出发量至少1,000班、有效轮转链至少500条”的机场：97 个；
- 当前 `v0-data.json` 只保存其中44个机场（压力 Top 30 与航班量 Top 30 的并集）；
- 当前首屏地图是压力数据机场、48条主要航线端点、4个故事机场的并集，共52个节点；
- 当前压力榜每种排序只显示前12个；
- MSY 的 `82.7` 是压力指数（满分100），不是第83名；在当前压力排序里是第8名；
- 精神航空 `NK` 的354条记录来自 BTS 原始月度文件且只发生在5月1日，并非前端抄错；但它不属于可比较的完整月度航司样本。

## 总体原则

优先级：

1. 指标和样本语义正确；
2. 普通访客一眼知道当前看的是哪个指标；
3. 鼠标、键盘和手机点按都能完成选择；
4. 中文模式真正中文优先；
5. 保持现有深色航空网络视觉，不重做整站。

不得把全国每日指标伪装成逐机场每日指标；机场压力数据仍是月度聚合。

## Phase 1：修正数据输出范围

### 1A. 压力榜使用完整97机场样本

当前 `build_airports` 在97个合格机场中又截取“压力 Top 30 ∪ 航班量 Top 30”，导致取消率、传播率等排序不一定是真正的97机场 Top 12。

修改为：

- `v0-data.json` 的压力榜机场数据保存全部97个合格机场；
- 压力指数仍在这97个机场内部按现有公式计算，不改权重；
- 前端每种排序从完整97机场中取前12名；
- 不把347个原始机场写成压力榜样本；
- 数据元信息至少增加：
  - `rawAirports`；
  - `eligibleAirports`；
  - `mapAirports`；
  - `rankedAirportsShown`。

### 1B. 首屏地图仍控制在代表性节点范围

不要因为压力榜扩展到97个机场，就直接把97个节点全部塞进首屏。

请把“压力榜完整样本”和“地图展示节点”解耦：

- 地图继续使用可解释的代表性机场集合，目标约52个；
- 至少包含原先的44个代表机场、48条底网的所有端点和4个故事的所有机场；
- 建议在数据层输出明确的 `mapAirportCodes` 或等价结构；
- `NetworkHero` 不再默认遍历全部压力榜机场来生成节点；
- 页面必须显示实际地图节点数量，不得硬编码。

### 1C. 航司比较设置可比门槛

用户已明确要求删除精神航空。

采用可复算规则，不只在 JSX 中硬编码隐藏：

- 航司比较仅保留月计划航班量 `>= 10,000` 的报告航司；
- 该规则在本月应得到12家航司，`NK` 不进入 `airlines` 展示数据；
- 页面航司说明写明“比较月计划航班至少10,000班的报告航司”；
- 不制作精神航空异常卡，不在航司对比正文中讨论精神航空；
- 如需保留原始报告航司总数，只能放在数据元信息中，并与“可比航司12家”分开命名。

## Phase 2：首屏指标选择与视觉编码

### 2A. 增加全国每日指标选择器

在日期控制区增加清楚的三选一控件：

- 起飞延误率；
- 取消率；
- 延误传播率。

默认选择起飞延误率。中文和英文同步。

### 2B. 选中指标驱动完整视觉

每个指标分别使用其31天真实序列做自己的 min–max / 分位数归一化。选中哪个指标，以下内容全部同步：

- HUD 的主数值和指标名称；
- 低 / 中 / 高等级；
- 地图背景能量；
- 航线透明度；
- 粒子亮度 / 速度；
- 节点尺寸与光晕；
- 31日趋势图；
- 日期滑块的 `aria-valuetext`；
- 图下注释和图例说明。

不得继续让取消率和传播率只变化数字、不影响地图。

明确写出：这是“全国每日指标驱动的整体网络强度”，不是每个机场当天的真实状态。

### 2C. 让视觉规则可以被读懂

在不过度增加文字的前提下，用短图例说明：

- 更大的节点 / 更强的光晕 = 当前全国指标更高；
- 更亮的航线 / 信号 = 当前全国指标更高；
- 机场之间的相对位置和月度压力颜色不代表逐日机场值。

最低日与最高日必须在三种指标下都能通过控件访问；至少对默认延误率保留肉眼明显的低高差异。

## Phase 3：聚合机场改成真正可选择

### 3A. 分离悬停预览与点击固定

当前只有 `hovered`，鼠标从 canvas 移向 HUD 时内容消失。改为至少两层状态：

- 悬停聚合节点：临时预览组内机场；
- 点击 / 点按聚合节点：固定打开机场选择面板；
- 点击地图空白、关闭按钮或按 Escape：关闭固定面板；
- 手机不能依赖 hover。

### 3B. 面板里的机场必须可选

聚合面板内每个机场代码是明确的按钮或可聚焦选项：

- 点选机场后，在面板中显示机场代码、中文名称 / 英文副名、城市、月度起飞延误率和压力指数；
- 对未进入97机场压力榜样本、但因航线或故事出现在地图上的机场，明确显示“地图航线节点，未进入压力榜样本”；
- 不得显示伪造的 `0.0%` 或 `压力0`；
- 键盘可 Tab 进入，焦点状态清楚；
- 英文模式显示对应英文信息。

如果单机场节点仍使用悬停 tooltip，也要支持点击固定，避免只有鼠标用户能读。

## Phase 4：压力榜展示逻辑修正

### 4A. 行内指标跟随排序

当前信号条已随排序变化，但右侧两列固定为起飞延误和传播率。改为动态主指标：

- 压力指数：`82.7 / 100`；
- 起飞延误：百分比；
- 延误传播：百分比；
- 航班量：整数 + `班`；
- 取消率：百分比。

表头、每行数值、相对信号条、无障碍标签都必须同步当前排序项。

用户要求是“按什么排，就展示什么数据”。不要让固定的延误率 / 传播率列继续占据主位。

### 4B. 分数和名次消歧

机场详情头部不能再只显示裸数字 `82.7`。

至少明确展示：

- `压力指数 82.7 / 100`；
- `97个合格机场中，第 N 名`（N 必须对应当前排序或明确写“压力指数排名”）；
- 当前榜单是“前12 / 97”，不是地图52机场排名，也不是347机场全国排名。

切换排序后，详情区域应显示当前排序项的标签、数值和该机场在97机场中的真实位置。不要只计算当前可见12行内的位置。

### 4C. 样本范围文案

用短而明确的文字区分：

- 全国每日指标：BTS 覆盖的611,735条航班记录；
- 压力榜：97个满足门槛的机场；
- 地图：约52个代表性节点，实际数量由数据生成；
- 榜单：当前排序前12名。
