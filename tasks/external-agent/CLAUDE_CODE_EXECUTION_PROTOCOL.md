# Claude Code 外部执行协议

最后更新：2026-07-28

## 目的

Claude Code 作为 Codex 可调用的外部代码执行器，负责边界已经冻结后的繁琐实现工作。Codex 仍负责需求澄清、版本边界、任务拆分、科学定义、风险控制和最终验收。

这不是 Codex 内置 subagent。双方共享同一个项目工作区，但不共享聊天上下文；因此每次正式任务都必须先写入 `tasks/external-agent/` 下的任务 MD。

## 模型与推理强度

- 正式代码任务固定显式指定 `--model gpt-5.6-luna`，不依赖 Claude Code 的默认别名或模型映射。
- 正式实现、重构和复杂排错默认使用 `--effort xhigh`。
- 小型只读诊断最低使用 `--effort high`。
- `low` 仅允许用于无工具、无文件修改的连通性探针；不得用于正式项目任务。
- 2026-07-28 已实际验证 `gpt-5.6-luna` 可通过当前中转站成功返回；本次探针不代表正式任务的 effort 配置。

## 标准执行方式

Codex 在项目根目录调用本机 `claude.cmd`，并明确传入模型、effort 和任务文件。示意命令：

```powershell
claude.cmd -p `
  --model gpt-5.6-luna `
  --effort xhigh `
  --permission-mode acceptEdits `
  "阅读 tasks/external-agent/<TASK>.md，严格按边界修改原项目文件，完成后把执行记录和验证结果追加回任务文件。"
```

实际命令可按任务需要增加流式输出、允许工具或恢复 session 的参数，但不得省略显式模型、effort 和任务入口。

## 权限与边界

- 默认允许读取和修改当前项目工作区、运行项目测试与构建。
- 不使用 `--dangerously-skip-permissions`。
- 未经用户明确授权，不得提交、推送、发布、安装系统软件、修改全局配置或删除重要数据。
- API Token 和中转站凭据不得写入任务 MD、日志、提交或最终报告。
- Codex 与 Claude Code 不得同时编辑同一文件；Claude Code 执行期间，Codex 以监督为主。
- 任务范围不清时，Claude Code 应停止扩张；由 Codex 补写边界后再继续。

## 任务文件必须包含

1. 当前版本和目标结果。
2. 允许修改与禁止修改的范围。
3. 数据或产品定义，以及不能擅自放宽的硬门槛。
4. 预计修改的文件和必须运行的验证命令。
5. 完成记录区：实际修改文件、执行命令、测试结果、未解决问题。

Claude Code 必须直接修改原项目文件，不另建一套平行实现。任务完成后应更新同一份任务 MD，便于 Codex 验收。

## Codex 验收职责

Claude Code 的“完成”不等于项目 GO。Codex 必须独立完成：

1. 检查工作区状态与 diff，确认无越界修改。
2. 阅读关键实现，而不是只接受执行器总结。
3. 重新运行数据测试、lint、build 和必要的浏览器交互。
4. 对科学定义、统计结果和界面叙事做一致性检查。
5. 将结果判定为 GO、CONDITIONAL GO 或 NO-GO；不通过时把具体返工项写回任务 MD。

## 卡住或中断时

- 长任务使用可监控的终端 session；Codex 定期读取新输出，不依靠用户反复提醒。
- 无输出时先区分正常长计算、权限等待、网络故障和模型接口故障。
- 需要时可终止本次 Claude Code 进程，再用任务文件和 session 信息恢复；不得无限静默重试。
- 外部模型不可用不自动扩大权限，也不自动降低验收门槛；Codex 可以接管剩余工作。
