# 外部代码执行协议（当前：WorkBuddy HY3）

最后更新：2026-07-30

## 目的

当前外部代码执行只使用 **WorkBuddy + HY3**。HY3 当前免费期截至 **2026-08-06**。它不是 Codex 内置 subagent，与 Codex 共享项目工作区但不共享聊天上下文；每次正式任务都必须先写入 `tasks/external-agent/` 下的任务 MD。Codex 仍负责需求澄清、版本边界、任务拆分、科学定义、风险控制和最终验收。

如果 HY3 联系不上、明确不适合当前任务，或多轮返工仍不正确，**由 Codex 直接接管**。不得自动切换到中转站 GPT-5.6 Luna。Luna 当前仅保留历史备用记录；是否恢复使用，等待用户在 2026-08-06 前后主动讨论，并在达成新决定后重新修改本协议。

## 当前执行选择规则

| 执行者 | 默认适用范围 |
|---|---|
| Codex 直接实现 | 小型文案、局部 UI、简单 Bug、预计半小时以内且无需大量机械代码的修改 |
| WorkBuddy / HY3 | 大型、机械实现多、边界已经写清楚的代码任务；2026-08-06 前使用当前免费期 |
| Codex 接管 | HY3 联系不上、明确不适合或多轮返工仍不正确 |
| Claude Code / GPT-5.6 Luna | 当前停用；只有用户重新讨论并更新规则后才能恢复 |

不要为了“免费”把不清楚的需求直接扔给 HY3。一次任务只指定一个主执行器，完成后统一由 Codex 验收；HY3 失败后由 Codex 接管，并在任务 MD 中记录交接原因。

## Claude Code / Luna 历史备用信息（当前停用）

- 正式代码任务固定显式指定 `--model gpt-5.6-luna`，不依赖 Claude Code 的默认别名或模型映射。
- 正式实现、重构和复杂排错默认使用 `--effort xhigh`。
- 小型只读诊断最低使用 `--effort high`。
- `low` 仅允许用于无工具、无文件修改的连通性探针；不得用于正式项目任务。
- 2026-07-28 已实际验证 `gpt-5.6-luna` 可通过当前中转站成功返回；本次探针不代表正式任务的 effort 配置。

## 上下文与 Codex 额度控制

- 一个主要版本或里程碑验收完成后，先把稳定状态写入 `PROJECT_STATUS.md` 与 `HANDOFF.md`，再优先新开 Codex 对话继续下一阶段。新对话只需读取这两份文件及当前任务书，不需要继承整段历史聊天。
- 超长对话会增加每轮需要处理的上下文；阶段性总结后换新对话，是本项目默认工作方式，不代表项目中断或重新开始。
- 小型文案、局部 UI、简单 Bug 和预计半小时以内的修改，默认由 Codex 直接完成。只有边界清楚、代码量较大、适合批量执行的工作才交给 HY3；HY3 失败后由 Codex 直接接管，避免额外执行器切换和重复交接。
- Codex 日常实现与普通验收优先使用 `high`；只有科学口径设计、复杂数据推导、疑难根因分析等任务才使用 `xhigh`。外部执行器的 effort 仍按任务风险单独指定。
- 浏览器验收必须使用目标组件、目标选择器和必要字段做定向检查；禁止为了核对少量文字反复读取整页 DOM、整页 `textContent` 或巨大截图/Base64。能用自动化测试确认的内容不重复用全页浏览器快照确认。
- 测试先定向、后集中全量：实现未稳定前只跑相关测试，稳定后统一跑一次 lint、build、SSR 和必要全量回归，避免无意义重复。
- HY3 在 2026-08-06 前免费，不代表 Codex 的编排、阅读、返工和验收免费。HY3 应承担真正的大块工作，Codex 保留科学定义和最终验收，但验收输出应保持精确、简短。

新对话推荐开场：

```text
读取 PROJECT_STATUS.md 和 HANDOFF.md，了解当前项目状态；再读取当前阶段的 tasks/external-agent 任务书。不要重做已标记 GO 的版本，不要提交或部署，先告诉我下一步边界。
```

## Claude Code / Luna 历史执行方式（当前不得自动使用）

Codex 在项目根目录调用本机 `claude.cmd`，并明确传入模型、effort 和任务文件。示意命令：

```powershell
claude.cmd -p `
  --model gpt-5.6-luna `
  --effort xhigh `
  --permission-mode acceptEdits `
  "阅读 tasks/external-agent/<TASK>.md，严格按边界修改原项目文件，完成后把执行记录和验证结果追加回任务文件。"
```

实际命令可按任务需要增加流式输出、允许工具或恢复 session 的参数，但不得省略显式模型、effort 和任务入口。

正式非交互实现还必须显式允许任务所需的项目工具，例如 `Read/Edit/Write/Glob/Grep/Bash`；仅使用 `acceptEdits` 可能允许文件编辑但阻止 Python、pytest 或 npm 命令，导致执行器在没有实现的情况下错误停为 NO-GO。若用户要求只使用 Luna，可通过项目内不含凭据的临时 settings 覆盖各默认模型槽位，并禁用 `Task` 子代理；不得为此修改用户全局配置。

### Codex 桌面环境的网络权限

本机 Claude Code 中转站配置保存在用户级 `.claude/settings.json`，不是 Windows 全局环境变量。Codex 通过命令工具启动 `claude.cmd` 时，必须使用允许外部网络的升级执行权限；默认 workspace 沙箱可以解析并 ping 中转站域名，但会阻止到中转站的 TCP 443 连接，从而让 Claude Code 最终显示 `ConnectionRefused`。

已于 2026-07-28 验证：

- 默认受限命令环境：中转站 DNS/ping 正常，TCP 443 失败；
- 允许外部网络后：同一中转站 TCP 443 成功；
- `gpt-5.6-luna` 无工具探针正常返回 `CONNECTED`。

因此以后遇到 `ConnectionRefused`，先核对本次 `claude.cmd` 是否以外部网络权限启动，不要直接判定中转站故障，也不要仅靠重复运行同一条受限命令解决。

## 权限与边界

- 默认允许读取和修改当前项目工作区、运行项目测试与构建。
- 不使用 `--dangerously-skip-permissions`。
- 未经用户明确授权，不得提交、推送、发布、安装系统软件、修改全局配置或删除重要数据。
- API Token 和中转站凭据不得写入任务 MD、日志、提交或最终报告。
- Codex 与 Claude Code 不得同时编辑同一文件；Claude Code 执行期间，Codex 以监督为主。
- 任务范围不清时，Claude Code 应停止扩张；由 Codex 补写边界后再继续。

## 任务文件必须包含

1. 当前版本和目标结果。
2. 允许修改与禁止修改的范围。
3. 数据或产品定义，以及不能擅自放宽的硬门槛。
4. 预计修改的文件和必须运行的验证命令。
5. 完成记录区：实际修改文件、执行命令、测试结果、未解决问题。

Claude Code 必须直接修改原项目文件，不另建一套平行实现。任务完成后应更新同一份任务 MD，便于 Codex 验收。

## Codex 验收职责

Claude Code 的“完成”不等于项目 GO。Codex 必须独立完成：

1. 检查工作区状态与 diff，确认无越界修改。
2. 阅读关键实现，而不是只接受执行器总结。
3. 重新运行数据测试、lint、build 和必要的浏览器交互。
4. 对科学定义、统计结果和界面叙事做一致性检查。
5. 将结果判定为 GO、CONDITIONAL GO 或 NO-GO；不通过时把具体返工项写回任务 MD。

## 卡住或中断时

- 长任务使用可监控的终端 session；Codex 定期读取新输出，不依靠用户反复提醒。
- 无输出时先区分正常长计算、权限等待、网络故障和模型接口故障。
- 需要时可终止本次 Claude Code 进程，再用任务文件和 session 信息恢复；不得无限静默重试。
- 外部模型不可用不自动扩大权限，也不自动降低验收门槛；Codex 可以接管剩余工作。
